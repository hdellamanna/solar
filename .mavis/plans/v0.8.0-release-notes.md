# v0.8.0 — Auth Phase 2 (Password Reset)

## Highlights

- **Forgot / reset password flow** — `Esqueci minha senha` link on the login
  page; email-based 60-min single-use reset link; auto-login after success.
  Same security model as email verification: SHA-256-hashed bearer tokens,
  raw token never stored, signed URL with 60-min TTL.
- **No user enumeration** — `POST /forgot-password` always returns the same
  success flash whether the email exists or not, and the email is gated by
  the same throttle (1 per 30s, max 5 per hour per address).
- **Single-use tokens, no replay** — the service-layer check refuses
  consumed / expired tokens; remember-me cookies are rotated on every
  successful reset; pending sibling tokens are invalidated when one is
  consumed.
- **Unverified users can reset** — the reset email serves as a soft
  re-verify path, so a user who never verified their inbox can still
  recover their account.
- **One table, two purposes** — the `email_verification_tokens` table
  gained a `purpose` column with a CHECK constraint
  (`email_verification | password_reset`); both flows share the same
  single-use SHA-256-hashed-token shape, lookup, and cleanup. PR3
  (2FA) will reuse the same table with `purpose = 'two_factor'`.

## Infrastructure

- 3 sequential hotfixes landed on `feature/auth-p2-backend` mid-cycle,
  all caught by the parallel test track before they could ship to
  production:
  - `Illuminate\Support\Facades\Str` → `Illuminate\Support\Str`
    (the Str facade was removed in Laravel 13).
  - `Route::post('/reset-password')` moved out of the `guest`
    middleware group so the post-reset auto-login does not
    short-circuit the single-use replay check via
    `RedirectIfAuthenticated`.
