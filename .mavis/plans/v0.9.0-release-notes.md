# v0.9.0 — Auth Phase 3 (2FA + Trusted Devices)

## Highlights

- **TOTP-based 2FA** with optional trusted-device cookies (90-day httpOnly,
  revocable). Reuses the same `email_verification_tokens` table with
  `purpose = 'two_factor_enroll' | 'two_factor_disable'` for the
  email-confirmed actions (same SHA-256-hashed single-use shape as
  verify and reset), plus session-state for the live login challenge.
- **TOTP secrets are app-key-encrypted at rest** (`Crypt::encryptString`).
  Replay protection via the `last_counter` field (refuses the same
  30s step twice).
- **10 single-use recovery codes** generated at enrollment, shown
  once, then SHA-256 hashed. Either the TOTP code OR a recovery
  code completes the challenge.
- **Hybrid smart enforcement** — 2FA challenge always fires on
  the live login (no skip), but the user can opt out of the
  trusted-device cookie per session. "Revoke all devices" clears
  the cookie and the `trusted_devices` table.
- **Destructive disable** — turning 2FA off wipes the encrypted
  secret + all recovery codes + all trusted devices, and logs
  the user out (defense in depth: email link + password re-prompt).
- **One table, three purposes** — the `email_verification_tokens`
  table now serves all three auth flows (`email_verification` |
  `password_reset` | `two_factor_enroll` | `two_factor_disable`),
  via the `purpose` column with a CHECK constraint. FASE 4D is
  complete: verify, reset, 2FA. The auth surface is now
  competitive with Linear / GitHub / Notion.

## Infrastructure

- 2 sequential hotfixes landed on the `feature/auth-p3-frontend`
  track mid-cycle, caught by the owner finalizing the work after
  the worker hit timeout:
  - `ConfirmTwoFactorDisableRequest`: drop `current_password`
    rule (user is NOT authenticated at that endpoint — the email
    token IS the credential; the service layer re-checks the
    password against the user identified by the token).
  - `VerifyTwoFactorRequest`: extend `code` field max length
    10 → 12 to fit the recovery-code format (`XXXX-XXXX-XX`).
  - `routes/web.php`: move the 2FA confirm POSTs OUT of the
    `signed` middleware group (the credential is the `token`
    field in the request body, not in the URL — `signed` would
    reject every legitimate POST). GETs with the token in the
    URL stay `signed`.
